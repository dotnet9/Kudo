## 结论

1. 500 Node / 1000 Edge 的常用编辑规模下，纯即时绘制与混合 Control 场景的连续平移、Zoom Median 均低于 10 ms；混合 Zoom P95 为 15.470 ms，已接近 60 Hz 单帧预算，但仍适合作为后续同机回归基线。
2. 2000 Node / 4000 Edge 压力规模下，稳态 Median 仍为 7.672～12.493 ms，说明路径缓存、空间索引和视口裁剪已经把主要工作限制在可见区域；但 P95 上升到 18.976～28.855 ms，尾部帧仍会超过 16.67 ms。
3. 2000 Node 首次 Render Median 为 466.942～486.741 ms，当前线程分配为 622.58～634.64 MB；同场景冷刷新全部 Edge 路径已占 422.532 ms 和 611.41 MB，证明首帧瓶颈主要来自冷 SmartOrthogonal 路由与几何建立，而不是轻量 Control 本身。
4. 500 Node 下嵌入 Control 对平移 Median 的影响较小，Zoom Median 由 8.599 ms 增至 9.303 ms；到 2000 Node 时，混合场景平移和 Zoom Median 分别增至 10.181 ms 与 12.493 ms。当前每次 Viewport 变化仍会遍历全部 Control Host 并更新布局，下一步应复用 Node 空间索引维护可见 Host 集合，同时保留离屏 Control 实例及 OpenGL Context。
5. 100 Node 的首次 Render 和部分混合场景数据受样本数、固定 workload 顺序及进程内全局缓存影响，不能据此得出“嵌入 Control 更快”的结论。

## 限制与下一步

1. 首次 Render 只有 3 个正式样本，P95 接近样本最大值；它表示 JIT 和全局 Skia 缓存预热后的新 Canvas 冷几何首帧，不是应用进程冷启动时间。
2. 轻量 Border + TextBlock 只代表 Visual Tree、布局与合成的基础成本，不能外推到复杂模板、TextBox、视频或 OpenGL Control。
3. 图数据不包含 Group、Runtime 动画、选择 Overlay、Edge Label 和 Marker；当前线程分配也不包含其他线程、Skia Native 或 GPU 内存。
4. workload 在同一进程内按固定顺序运行，结果会受 Tiered PGO、后台负载和电源计划影响；手工发布门禁只执行 Smoke，不设置绝对耗时门禁。
5. 后续仍需为冷 SmartOrthogonal 路由和批量加载建立独立基准，降低 2000 Node 首帧耗时及分配。

## 后续验证：SmartOrthogonal 增量路由失效

2026-08-19 将节点几何变化从全局障碍版本失效改为保守的局部失效。默认障碍 Provider 会保留上一次不可变快照，分别计算节点或折叠 Group 的旧、新障碍范围，并按当前 `ObstaclePadding` 扩张；缓存层只删除端点关联 Edge，以及路径包围范围与这些区域相交的 SmartOrthogonal Edge。未受影响路径继续沿用原缓存，Edge 空间索引只替换相同受影响集合。

以下情况仍使用全量 SmartOrthogonal 失效：旧障碍快照不存在、使用自定义 `IGraphEdgeObstacleProvider`、Group 定义或折叠状态变化、路由属性变化，以及结构变更。全量智能失效不会清除无关 Direct、Bezier、Orthogonal 或 Manual 路径；Document 和路由服务配置变化仍清空全部路径缓存。

Avalonia 行为测试覆盖远处障碍移动、障碍移入与移出路径、端点移动、多节点批量变化、折叠 Group、自定义 Provider 回退、普通 Edge 缓存保持、路由配置全量失效，以及增量重路由后的 Edge 空间索引命中。
